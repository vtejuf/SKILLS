# 5步开发法 - 项目应用版

基于AI协同开发指南的精简版本，专注于实际项目开发中的5步法应用。

## 核心流程

### 五阶段递归模型
```
需求理解 → 开发 → 测试 → 总结收尾 → 归档
```

**每个阶段完成后必须提交Git**：
- 阶段1：`feat: 完成需求理解阶段 - [项目描述]`
- 阶段2：`feat: 完成开发阶段 - [功能描述]`
- 阶段3：`test: 完成测试阶段 - [验证内容]`
- 阶段4：`docs: 完成总结收尾 - [项目总结]`
- 阶段5：`docs: 完成归档阶段 - [知识沉淀]`

## 阶段详解

### 1. 需求理解
**目标**：明确项目目标、约束和交付物
**关键动作**：
- 分析用户需求，澄清模糊点
- 识别关键约束和边界条件
- 制定初步技术方案
- **提交Git**：记录需求分析结果

### 2. 开发
**目标**：将需求转化为可运行代码
**关键动作**：
- 设计技术方案（必要时提供对比）
- 实现核心功能（MVP优先）
- 遵循现有代码风格和规范
- **提交Git**：记录功能实现

### 3. 测试
**目标**：验证功能正确性，发现问题
**关键动作**：
- 功能测试：基本功能是否正常
- 边界测试：极端情况处理
- 异常测试：错误处理机制
- **提交Git**：记录测试结果

### 4. 总结收尾
**目标**：完成交付，准备干净上下文
**关键动作**：
- 确认所有需求已实现
- 更新相关文档（如SKILL.md）
- 明确项目结项状态
- **提交Git**：记录项目总结

### 5. 归档
**目标**：沉淀知识，便于复用
**关键动作**：
- 提炼可复用模式和经验
- 生成项目档案
- 标记可复用组件
- **提交Git**：记录知识沉淀

## 递归处理子需求

当项目包含子需求时，每个子需求同样完整经历5个阶段：

```
核心需求
├── 阶段1：需求理解
├── 阶段2：开发
│   ├── 子需求1：完整5阶段
│   ├── 子需求2：完整5阶段
│   └── ...
├── 阶段3：测试
├── 阶段4：总结收尾
└── 阶段5：归档
```

## 关键原则

### 1. 强制提交
- 每个阶段完成后必须提交Git
- 只提交不推送（保护本地历史）
- 通过`git revert`回滚，不重写历史

### 2. 上下文管理
- 总结收尾阶段必须清理临时信息
- 为下一阶段/项目准备干净上下文
- 项目间依赖通过文档传递，而非记忆

### 3. 小步快跑
- 大需求拆解为小需求
- 快速迭代，持续验证
- MVP优先，逐步增强

## 使用示例

### 新项目开始
```
用户：开发数据源适配器SKILL
AI：调用five-step-dev SKILL
    阶段1：需求理解 → git commit
    阶段2：开发 → git commit
    阶段3：测试 → git commit
    阶段4：总结收尾 → git commit
    阶段5：归档 → git commit
```

### 子需求处理
```
在开发阶段发现子需求：
AI：处理子需求（完整5阶段）
    子需求阶段1：需求理解 → git commit
    子需求阶段2：开发 → git commit
    ...
完成后继续父需求的后续阶段
```

## 检查清单

### 需求理解阶段
- [ ] 目标明确无歧义
- [ ] 约束条件清晰
- [ ] 交付物可量化
- [ ] 双方达成一致

### 开发阶段
- [ ] 技术方案确认
- [ ] 核心功能实现
- [ ] 代码风格一致
- [ ] 错误处理完善

### 测试阶段
- [ ] 功能测试通过
- [ ] 边界情况处理
- [ ] 异常处理正确
- [ ] 无严重缺陷

### 总结收尾阶段
- [ ] 所有需求已实现
- [ ] 文档准确完整
- [ ] 上下文清理完成
- [ ] 项目明确结项

### 归档阶段
- [ ] 知识已沉淀
- [ ] 可复用资产标记
- [ ] 项目档案完整
- [ ] 便于后续复用

## 注意事项

1. **不要跳过提交**：每个阶段完成后必须提交
2. **保护历史记录**：通过`git revert`回滚，不重写历史
3. **清理上下文**：总结收尾阶段必须为下一阶段准备干净上下文
4. **递归处理**：子需求同样完整经历5个阶段
